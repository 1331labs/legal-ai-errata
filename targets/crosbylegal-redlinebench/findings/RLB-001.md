## Defect
`DocumentView.load` in `skills/contract-redliner/scripts/redline_engine/document.py` (line 88) builds its paragraph list from `doc.paragraphs`, which in python-docx 1.2.0 (the version pinned in each task's Dockerfile) returns only paragraphs that are direct children of the document body and omits paragraphs inside table cells. The same class feeds the agent's `read_document.py`, anchor resolution in `anchoring.py` (line 111), the validity gate in each task's `tests/judge.py` and the judge's rendered view in each task's `tests/annotated_view.py` (dataset files). The task instruction (line 180 of instruction.md in s1-t1-g01a; the same sentence appears in all 140 tasks, at lines 179 to 198) requires the agent to use these scripts for every read and every edit and forbids any other way of modifying the file. An agent therefore cannot see or edit the Exhibit A and Exhibit B severity and service-credit tables through the supplied tools, and a table edit made by any other route does not appear in the text the judge grades. Nineteen criteria in eleven tasks, with a combined weight of 136, call for an insertion, deletion, replacement or rejection whose target is the content of a table cell: s1-t1-g01a #11, #13; s1-t1-g01b #18; s1-t1-g01d #12, #13, #14; s1-t3-g02a #7; s1-t3-g08a #6; s1-t4-g01a #5, #6, #7, #8; s1-t4-g02a #8; s1-t4-g05a #9; s1-t4-g06a #9; s1-t4-g09a #2; s2-t2-g02c #9, #10, #11 (task ids without the `redline-` prefix; #n is the 1-based index in that task's `tests/rubrics.json`). In 18 of the 19 the attorney reference redline meets the criterion with a tracked change inside a table cell, so the reference itself cannot be seen to meet it in the published judge view; in the remaining one (s1-t3-g08a #6) the counterparty insertion to be rejected sits in a table cell and the reference answers it by comment only. The same file is vendored unchanged in 280 places in the dataset (`tests/redline_engine/document.py` and `environment/skills/contract-redliner/scripts/redline_engine/document.py` of each of the 140 tasks), all of which need the fix.

The same class also prints the body without its pending tracked changes. `ParagraphInfo.text` is `p.text` (document.py line 93), which in python-docx 1.2.0 joins only the `w:r` and `w:hyperlink` children of the paragraph and so leaves out every run inside `w:ins`, `w:del`, `w:moveTo` and `w:moveFrom`; `to_markdown` prints that text (line 147) and skips any paragraph whose `p.text` is blank (lines 137 to 139). The instruction of each of the 126 turn 2 to 4 tasks (line 140 in s1-t2-g01a; line 139 or 140 in the others) tells the agent that `read_document.py` output shows the counterparty's changes inline, but the printed body is neither the earlier wording nor the wording as changed: inserted words are missing, deleted words are missing, and a paragraph whose only text is a pending insertion is not listed at all. The changes appear only in the appendix, by revision id and paragraph id, without their position in the sentence.

## Proposed correction
In skills/contract-redliner/scripts/redline_engine/document.py, and in each of the 280 vendored copies in the dataset:

old: `        for i, p in enumerate(doc.paragraphs):`
new: `        for i, p in enumerate(_iter_all_paragraphs(doc)):`

and add before `_paragraph_has_revisions`:

```python
def _iter_all_paragraphs(doc: DocxDocument) -> Iterable[Paragraph]:
    """Yield body paragraphs in document order, including table-cell paragraphs.

    `doc.paragraphs` returns only the direct children of the body, so text and
    tracked changes inside `<w:tbl>` (SLA tables, credit tables, signature
    grids) never reach the reader, the anchoring code or the judge view.
    Paragraphs nested inside another paragraph (text boxes) are skipped so
    their text is not emitted twice.
    """
    p_tag = qn("w:p")
    for p_el in doc.element.body.iter(p_tag):
        if any(a.tag == p_tag for a in p_el.iterancestors()):
            continue
        yield Paragraph(p_el, doc._body)  # noqa: SLF001
```

In `to_markdown`, in the same files:

old:
```python
        for p in self.paragraphs:
            if p.is_empty:
                continue
```
new:
```python
        for p in self.paragraphs:
            text = self._body_text(p)
            if not text.strip():
                continue
```

old: `            lines.append(f"[{p.id}] ({p.style}){flag_str} {indent}{p.text}")`
new: `            lines.append(f"[{p.id}] ({p.style}){flag_str} {indent}{text}")`

with two helpers, `_render_with_revisions` and `_run_text`, added after `_paragraph_has_revisions`, and four lines added to the `to_markdown` docstring (full text in the patch). `_render_with_revisions` walks the paragraph's children in order: runs and hyperlinks give the same text as `Paragraph.text`; runs inside `w:ins` or `w:moveTo` are wrapped `++…++` and runs inside `w:del` or `w:moveFrom` are wrapped `~~…~~`; nested revisions (a deletion of another author's insertion) are rendered recursively; adjacent spans of the same kind are joined. A new method, `_body_text`, used by both `to_markdown` and `stats()`, returns that rendering for a paragraph that carries tracked changes and `ParagraphInfo.text` otherwise, so `stats()` counts as `non_empty_paragraphs` exactly the paragraphs `to_markdown` lists. A further helper, `_row_revision`, returns the `w:ins` or `w:del` mark that Word places in the row properties (`w:trPr`) when a whole table row is inserted or deleted, because the text of such a row need not carry a run-level mark of its own: paragraphs in that row are treated as carrying tracked changes, a paragraph in the row with no run-level mark of its own is wrapped `++…++` or `~~…~~` in full (`_row_paragraph_text`), one with run-level marks is rendered from them as before, and the row is listed once among the existing tracked changes. `ParagraphInfo.text`, `is_empty`, anchor resolution, the edit operations and the body text of the judge view are unchanged; only the body lines of paragraphs that carry tracked changes, paragraphs whose only text is a tracked change, the `non_empty_paragraphs` count of an input that contains such paragraphs, and, for a table row marked as inserted or deleted as a whole, the REVS flag and the tracked-change appendix of the agent's and the judge's views differ.

The patch file patches/rlb-001.patch contains both changes for the GitHub repository; patches/rlb-001-dataset.patch carries the identical hunks for the 280 dataset paths. Points for the maintainer: anchors still resolve against `ParagraphInfo.text`, the text outside tracked changes, so text shown inside `++…++` or `~~…~~` cannot be used as an anchor (the behaviour is unchanged; before the change that text was not shown in the body at all); paragraph ids after the first table shift, because ids are assigned by load order; table cells are rendered as consecutive paragraphs with no row or column label; `mark_reserved.py` over a range that spans a table now also strikes the cell text in that range; and published scores were produced with the earlier view. `src/rejudge.py` re-judges from each trial's saved `verifier/annotated_view.md` (src/judging.py lines 11 to 12; src/rejudge.py line 64), so for published trials that view must first be rendered again with the changed loader from the trial's saved output document (`artifacts/contract.docx`, which src/reproduce.py line 264 reads) before the 19 criteria are re-judged (the inline rendering changes only the agent's reader output, not the judge view); the reference redlines should be checked against the 19 criteria in the same way.

Patch: `patches/rlb-001.patch` (applies at upstream head b29d1113af on 2026-10-20).

## Objections considered
- Objection: Agents can and do edit tables by other means, so the criteria are earnable.
  Answer: instruction.md forbids modifying the file other than through the scripts, and the judge view is built from the same DocumentView, so a table edit made by any route is absent from the text the judge grades; the reference redline's own table edits are absent too.
- Objection: The fix breaks something else: paragraph ids shift, mark_reserved ranges now include cell text, Paragraph objects for cells are parented to the body, published scores change.
  Answer: The id shift and the reserved-range behaviour are real and are stated above under Proposed correction; they follow from including the cells and do not corrupt output (reader, replace, comment and reserved tools were run on table paragraphs and the result reloads). Parenting to the body does not affect text, style lookup or the docx-revisions operations exercised. Score changes are the purpose of the fix.
- Objection: Printing tracked changes inline is a design choice; the appendix already lists every change.
  Answer: The instruction of every turn 2 to 4 task tells the agent the body shows them inline, so the reader contradicts the task's own description of the tool the agent is required to use. The appendix gives each change's text and paragraph but not its position in the sentence, and a paragraph whose only text is a pending insertion is absent from the body. The rendering uses the `++…++` and `~~…~~` convention of the instruction and of the judge view in tests/annotated_view.py, and leaves anchor resolution and every other output unchanged.
